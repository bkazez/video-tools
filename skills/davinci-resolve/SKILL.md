# Driving DaVinci Resolve from outside

Resolve exposes a Python API that can build a whole project — bins, imports, clip
attributes, timelines — deterministically. `bin/build-resolve-project` wraps it
behind a YAML spec; this is what you need to know whether you use that or the API
directly.

## It only answers if it is running

    resolve = DaVinciResolveScript.scriptapp("Resolve")     # None if not

Two preconditions, and the failure for both is the same silent `None`:

- **Resolve must be open.** Launch it with `open -g -j -a "DaVinci Resolve"` so it
  does not steal focus, and give it a minute — the process appears long before
  the API answers.
- **Preferences → System → General → "External scripting using" must be Local.**

The env vars (`RESOLVE_SCRIPT_API`, `RESOLVE_SCRIPT_LIB`, `PYTHONPATH`) are
already set on this machine. If an import fails anyway, append the modules path
directly:
`/Library/Application Support/Blackmagic Design/DaVinci Resolve/Developer/Scripting/Modules/`

## Setting order matters, and a refused write is silent

`SetSetting` returns a boolean. **Check it**, because a refusal changes nothing
and reads back as the old value with no error.

The one that bites: with **`isAutoColorManage` = 1**, Resolve derives the output
colour space and refuses to set it. `colorSpaceOutput` then keeps reporting
something you did not choose (`Rec.709 (Scene)`) while `colorSpaceTimeline`
accepts your value perfectly — so the project looks configured and is not. Set
`isAutoColorManage` to `0` **first**, then the three spaces:

    isAutoColorManage: "0"
    colorSpaceInput:    Rec.709 Gamma 2.4
    colorSpaceTimeline: Rec.709 Gamma 2.4
    colorSpaceOutput:   Rec.709 Gamma 2.4

Not every plausible name exists. `useOptimizedMedia` is not a setting and returns
`''` forever; optimized media is generated by a user action, so the way to avoid
it is not to trigger it.

## Clip attributes are where log footage is won or lost

`MediaPoolItem.SetClipProperty(name, value)` — also boolean, also worth checking.
The names are not the ones the UI shows:

| Property | Note |
|---|---|
| `Data Level` | **Singular.** `Auto`, `Full`, `Video`. Not "Data Levels" |
| `Input Color Space` | e.g. `S-Gamut3.Cine/S-Log3`, `Rec.709 Gamma 2.4`. Defaults to `Project` |
| `FPS` | Settable, and this is the slow-motion fix |
| `Video Frame Rate`, `Shot Frame Rate`, `Super Scale` | read-only; setting them returns False |

**Log footage carries no tag that says it is log.** The container reports
`color_transfer=unknown`, so Resolve cannot infer it and will treat S-Log3 as
Rec.709 — which looks like a flat clip someone forgot to grade, not like a
mistake. Set `Input Color Space` explicitly, per clip or per bin.

**Data Level is a real decision, not a formality.** Sony XAVC S-Log3 is recorded
full range and flagged `pc`; the check is that S-Log3 black sits at 95/1023,
which decodes to 24/255 — measure `YMIN` on a frame and it should read 24. Guess
`Video` when it is `Full` and the blacks crush.

### FPS is how you undo S&Q slow motion

Setting `FPS` to the capture rate makes Resolve treat the media as that rate, so
it plays at real time. It is lossless — every captured frame is still used — and
you can see it work in the clip's own duration:

    C0490.MP4  FPS 25 -> Duration 00:07:53:07
    C0490.MP4  FPS 50 -> Duration 00:03:56:32     (236.6 s, the real length)

Get the capture rate from `sony-clip-info` (see the `camera-sync` skill). Do this
**before** building timelines: `startFrame`/`endFrame` count in the clip's own
frames, so they mean different things before and after.

## Building a timeline at exact positions

`CreateEmptyTimeline(name)` then `AppendToTimeline([clipInfo, …])`, one dict per
clip:

    {"mediaPoolItem": item, "mediaType": 1,        # 1 video, 2 audio
     "trackIndex": 1,
     "startFrame": int(start_seconds * clip_fps),  # CLIP frames, at its FPS
     "endFrame":   start + int(dur * clip_fps) - 1,
     "recordFrame": timeline_frame}                # TIMELINE frames

Two frame rates are in play and mixing them up is the usual bug: `startFrame`
and `endFrame` are in the **clip's** numbering (after any FPS override),
`recordFrame` is in the **timeline's**. A 50 fps clip in a 25 fps timeline is
conformed by Resolve and plays at real time.

`GetStartFrame()` is not necessarily 0 — timelines often start at hour one — so
place the first clip at `GetStartFrame()`, not at 0.

Creating a timeline whose name already exists returns `None` rather than
erroring, which makes re-running a build script safe but silent; report it.

## Disk

Optimized media and render cache for a folder of 4K originals will fill a disk
that looked fine. Check free space against the media size before offering to
generate either — on this machine the recordings volume has run at 44 GB free
against 190 GB of source for a single session. Working off the originals is
normally fine; Apple silicon decodes H.264 in hardware.

## Do not disturb what is already open

`GetProjectManager().GetProjectListInCurrentFolder()` before creating anything.
Ben has 50-plus projects in the disk database and one open in the GUI; create or
load by name and save with `SaveProject()` rather than closing his.

`--dry-run` expands the globs and lists what it would build without touching
Resolve. A worked spec, with the colour settings for a two-camera S-Log3 and
Rec.709 shoot, is
